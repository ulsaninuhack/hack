# UI/UX 심사 루브릭

조사원 모바일과 매니저 웹의 모든 UI 마일스톤에 적용한다. 하드 금지 항목은 하나라도 발견되면 즉시 실패다.

## 공통 하드 금지

### 문구와 구성

- 자기지시·홍보성 문구를 쓰지 않는다.
  - 금지 예: `누구나 쉽게`, `쉽고 간단`, `AI가 도와주는`, `스마트한`, `혁신적`, `한눈에`, `Welcome`, `간편하게`
  - 앱의 미덕을 설명하는 제목이나 히어로를 두지 않는다.
  - 특히 “누구나 쉽게 이해할 수 있는 ○○” 같은 제목을 쓰지 않는다.
- 대형 히어로, 3개 기능 카드, 장식용 그라데이션을 조합한 제너릭 AI 템플릿을 쓰지 않는다.
- 헤더에 이모지를 장식처럼 반복하지 않는다.
- 섹션 제목은 사용자의 할 일을 지칭한다.
  - 허용 예: `오늘 연락할 대상`, `통화(또는 방문) 결과 입력`, `방문 권고 승인`
  - 금지 예: `사용하기 쉬운 대시보드`

### 데이터와 상태

- 실제 주민의 이름·전화번호·호수·주민 속성을 만들거나 노출하지 않는다.
- 연락 대상은 내부 ID 대신 결정적 가명으로 표시하고, 화면 문맥에서 모든 이름이 가명인 데모임을 명시한다. 내부 ID는 API 요청 키로만 사용하며 화면과 접근성 라벨에 노출하지 않는다.
- 색만으로 상태를 구분하지 않는다. 색, 텍스트, 형태를 함께 사용한다.
- 매뉴얼 어휘인 `안부확인`, `연락업무`, `방문 권고`, `담당자 승인`, `이관`을 사용한다.
- 개인을 판정하는 표현을 쓰지 않는다. 금지 표현은 `위험도`, `고위험자`, `미수혜자`, `개인예측`이다.
- `no_answer` 같은 raw enum을 화면에 노출하지 않는다. 사용자에게는 `연락 안 됨`처럼 표시한다.

## 조사원 모바일

대상 사용자는 고령 연결단원이다.

- 본문은 18px 이상이고, 어떤 사용자 노출 글자도 16px 미만으로 만들지 않는다.
- 핵심 숫자와 라벨은 본문보다 크게 표시한다.
- 터치 영역은 가로·세로 모두 48px 이상이며 요소 간 간격을 충분히 둔다.
- 주요 액션은 화면 하단에서 한 손으로 닿는 위치에 고정한다.
- 한 화면에는 한 과업만 둔다.
- 통화(또는 방문) 결과 입력 단계를 최소화하고 가로 스크롤을 만들지 않는다.
- 아이콘만 있는 버튼을 쓰지 않는다. 아이콘과 글자를 함께 제공한다.
- 숫자에는 의미와 다음 행동을 함께 표시한다.
  - 예: `급성도 82 · 높음 · 지금 방문 검토`
- 등급은 숫자나 색뿐 아니라 말로도 표시한다.
- 삭제·취소 같은 파괴 액션은 확인 또는 되돌리기를 제공한다.
- 오류 메시지는 실패 이유와 사용자가 다음에 할 행동을 함께 말한다.
- 본문 대비는 WCAG AAA를 지향하고 최소 WCAG AA를 충족한다.

## 매니저 웹

대상 사용자는 비전문가인 9급 공무원이다.

- 각 뷰에는 명백한 주요 액션을 하나만 둔다.
- 해석이 필요한 정보를 촘촘하게 쌓은 대시보드를 만들지 않는다.
- 모든 숫자에 그 뜻과 담당자가 할 일을 주석으로 제공한다.
- 급성도와 취약도를 분리해서 표시한다.
- 각 점수에는 `왜 이 점수인지` 기여내역을 펼쳐 볼 수 있게 한다.
- 승인과 반려가 혼동되지 않게 한다.
- 담당자, 거리 제약, 메모를 명확한 필수필드로 표시하고 최종 확인 단계를 둔다.
- 약어와 전문용어를 피하고 차분한 공공서비스 어조를 사용한다.
- 스타트업 홍보 페이지 같은 시각 어조를 사용하지 않는다.

## 자동 게이트

하드 금지 문구는 `scripts/check-ui-copy.mjs`와 테스트로 검사하며 CI에서 실행한다. 루브릭 문서 자체는 금지 예시를 정의하므로 검사 대상에서 제외한다.

UI 마일스톤은 다음 객관 항목을 자동으로 검증하기 전 완료로 처리하지 않는다.

- 모바일 글자 크기: 본문 18px 이상, 모든 사용자 노출 글자 16px 이상
- 모바일 터치 타깃: 48×48px 이상
- 390×844 화면에서 가로 스크롤 없음
- 본문·상태 텍스트 WCAG AA 이상, 본문 AAA 지향
- axe 접근성 검사에서 critical/serious 위반 없음
- 아이콘 단독 버튼 없음
- 색상 외 텍스트 또는 형태 상태 표기 존재

앱 골격이 없는 저장소는 금지 문구 게이트부터 적용하고, 첫 UI 마일스톤 PR에서 나머지 자동 검사를 함께 추가한다.

## 생성과 평가 분리

1. 구현자는 UI를 만들고 자동 게이트를 통과시킨다.
2. UI 마일스톤마다 Vercel Preview URL을 `docs/PROGRESS.md`와 인수인계 문서에 기록한다.
3. 평가자는 Claude 브라우저로 Preview URL에 접속한다.
4. 모바일은 390×844, 데스크톱은 1440×900 기준 스크린샷을 남긴다.
5. Claude는 이 루브릭으로 독립 채점하고 위반 위치, 근거, 기대 수정안을 punch-list로 반환한다.
6. Codex는 punch-list를 수정하고 자동 게이트를 다시 실행한다.
7. Claude 재검토가 끝난 뒤에만 UI 마일스톤을 완료로 표시한다.

자동 검사는 글자 크기, 터치 영역, 대비, axe, 금지 문구 같은 객관 항목의 게이트다. 홍보성, 취향, 공공서비스 어조, 도메인 적합성의 최종 판정은 Claude 리뷰가 담당한다.
