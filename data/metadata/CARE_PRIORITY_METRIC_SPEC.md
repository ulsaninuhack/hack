# CARE 우선 발굴 지도 지표 명세

## 0. 문서 상태와 결론

- 상태: `v0.1 / metric design only`
- 기준일: 2026-08-12
- 의사결정: **인천시가 다음 현장 검토·아웃리치 계획을 세울 때 어느 행정동을 먼저 살펴볼지** 정한다.
- 현재 제공 가능한 결과: 주민등록상 65세 이상 1인세대의 **관측 규모와 관측 비율**을 함께 보여 주는 지역 단위 수요-context 지도
- 현재 제공할 수 없는 결과: 복지 미수혜자 수, 고독사 위험자 수, 개인별 위험 확률, 확정 돌봄 공백, 최종 종합점수

따라서 지금은 두 관측 지표를 나란히 보여 주는 **무가중 scorecard**를 사용한다. 아직 가중치를 부여하거나 하나의 `care_priority_score`로 합치지 않는다. 두 지표는 주민등록 인구·세대 구조를 설명하는 **수요 맥락 proxy**일 뿐이며, 실제 독거·사회적 고립·동거 여부·서비스 적격성·사례 건수·연락/방문 업무량을 측정하지 않는다. 지도는 현장 검토 순서를 돕는 도구이지 개인의 자격·위험을 판정하는 도구가 아니다.

## 1. 공식 I5 요구와 구현 경계

공식 안내자료 `raw/reference/hackathon_participant_guide_0810.pdf`의 `I5`는 원도심 중심 고독사·안전사고 발견 지연을 문제로 두고 다음을 AI 활용 방향의 예시로 제시한다.

1. 전력·수도 사용 이상징후 조기 감지
2. 돌봄 수요·공급 매칭을 통한 공백 지역 도출
3. 고위험 지역 시각화와 예방 자원 우선 배치

같은 자료의 `4-5. 보안·이용 수칙`은 개인정보를 AI 입력에 넣지 말고 생성 내용과 통계를 원자료로 검증하도록 요구한다. `5-8. 돌봄·안전 공백`은 KOSIS, 복지로, 건축데이터 개방, 한전 전력데이터, 사회보장 통계를 후보 출처로 들며 실데이터와 가상 데이터를 명확히 구분하도록 한다.

| I5 방향 | 이 데이터팩에서의 처리 | 상태 |
|---|---|---|
| 고위험 지역 시각화 | 주민등록상 65세 이상 1인세대 **규모·혼합-snapshot 비율**을 수요-context proxy로 표시. 고위험 지역 자체를 측정한다고 주장하지 않음 | 즉시 가능 |
| 돌봄 수요·공급 매칭 | 인구, 시설, 교통, 주택 자료는 확보했으나 시설 좌표·정원과 행정동 공간조인이 불완전 | 후보 지표만 정의 |
| 예방 자원 우선 배치 | 관측 지표로 검토 대상을 좁힐 수 있으나 실제 인력·시간·수용량이 없어 배치 최적화는 미검증 | 운영데이터 필요 |
| 전력·수도 이상징후 | 실사용량·사고 정답 데이터가 없음 | 합성 시뮬레이션만 허용 |

화면과 발표에서는 데이터 계보를 다음처럼 구분한다.

- `[OBSERVED AGGREGATE]`: 공개 집계자료에서 관측된 수·비율
- `[SYNTHETIC EVENT]`: 전력·수도 이상징후나 가구별 경보 시뮬레이션
- `[MODEL OUTPUT — UNVALIDATED]`: 검증 전 모델 산출물
- `[MUNICIPAL RECORD — REQUIRED]`: 지자체 내부 기록이 있어야 검증 가능한 운영 결과

## 2. 지표 계층

### 2.1 지금 사용하는 2개 핵심 관측 지표

두 지표는 서로 대체하지 않는다. 규모 지표는 주민등록상 65세 이상 1인세대의 수를, 비율 지표는 주민등록상 65세 이상 인구 대비 해당 1인세대 수를 보여 준다. 둘 다 **지역 수요-context proxy**이며 실제 생활 단독, 사회적 고립, 실거주 동거, 돌봄 필요, 서비스 적격성, 실제 사례 건수 또는 확정 업무량을 뜻하지 않는다.

| ID | 지표명 | 행정 의사결정 | 정확한 grain | 기준일 | 산식 | 로컬 원천과 필드 | 상태/주의 |
|---|---|---|---|---|---|---|---|

### 2.3 현재 적용하는 2개 guardrail

#### `G1` 의미·개인정보 guardrail

- 공개 집계만으로 “복지를 받아야 하지만 못 받는 사람”을 식별할 수 없다.
- 주민등록상 1인세대는 실거주 기준의 독거가 아니다. 미신고 동거, 주소-실거주 불일치, 시설 거주 등은 이 집계만으로 확인할 수 없고 사회적 고립이나 돌봄 필요도 추론할 수 없다.
- `P1`, `P2`, 향후 후보 지표를 `unserved_person_count`, `미수혜자 수`, `고독사 위험자 수`라고 부르지 않는다.
- `processed/welfare_basic_livelihood_2024_current_dong_mapping.csv`의 `recipient_count_living_*`, `recipient_count_medical_*`, `recipient_count_housing_*`, `recipient_count_education_*`는 급여 자격별 건수이며 같은 사람이 중복될 수 있다. 서로 합산해 수급자 수를 만들거나 `P1`에서 빼지 않는다.
- 2024년 복지자료와 2026년 인구자료는 기준시점·모집단·행정경계가 다르다. `processed/welfare_metric_recommendations.json`의 `overall_verdict=do_not_use_existing_potential_care_gap_proxy`를 강제 규칙으로 삼는다.
- 개인 주소·가구별 빨간 점은 표시하지 않는다. `processed/map_bubbles_age_65_plus_one_person_202607.geojson`의 점은 실제 가구가 아니라 구역 내부의 대표점이다.
- 합성 가구·이상징후는 항상 `[SYNTHETIC EVENT]`로 표시하고 실제 주민처럼 보이는 주소, 이름, 연락처를 생성하지 않는다.

#### `G2` 데이터 품질·공정성 guardrail

- 절대 규모만 쓰면 대규모 동이 유리하고, 비율만 쓰면 작은 분모의 동이 과대평가될 수 있으므로 `P1`과 `P2`를 항상 함께 본다.
- 현재 지도 경계는 2025-06-30의 156구역이고 통계는 2026-07-01의 162행정동이다. `processed/boundary_validation.json`에 명시된 2개 분할 집계와 4개 출장소-본소 집계를 유지하며 162개처럼 보이는 가짜 폴리곤을 만들지 않는다.
- 지도/표에는 `population_reference_date`, `household_reference_date`, `geometry_base_date`, `map_unit_status`, `mapping_confidence`를 노출한다.
- 개인·사건 자료가 들어오면 셀별 공개 최소 인원 기준은 지자체 개인정보·통계공개 담당자가 승인한 값으로 정한다. 승인 전에는 개인 마커와 소수 셀을 공개하지 않고 상위 지리로 집계하거나 숨긴다. 이 문서가 임의의 `k`를 정하지 않는다.
- 향후 모델은 구·도서/내륙·연령대·성별 등 법적으로 허용되고 충분한 표본이 있는 집단별로 **선정률, 실제 확인률, 응답시간, 미처리율**을 비교한다. 표본이 작은 집단은 불리함이 없다는 결론을 내리지 않고 불확실 구간과 함께 보류한다.

## 3. 지도에서 지금 내릴 수 있는 결정

`P1/P2`의 “높음/낮음” 절단값은 아직 고정하지 않는다. 첫 운영 시 분포와 현장 수용량을 본 뒤 검토 구간을 정한다. 그 전에는 연속값·순위·기준일을 그대로 보여 준다.

| 관측 패턴 | 허용되는 해석과 다음 행동 | 금지되는 해석 |
|---|---|---|
| `P1` 높음 + `P2` 높음 | 주민등록상 65세 이상 1인세대의 규모와 혼합-snapshot 비율이 모두 상대적으로 큰 지역이다. 담당자가 동일 시점 내부 사례·적격성·공급 자료를 추가 확인한다. | “미수혜자·고립가구·방문대상이 가장 많다” |
| `P1` 높음 + `P2` 낮음 | 주민등록상 65세 이상 1인세대 수는 상대적으로 크고 인구 대비 혼합-snapshot 비율은 낮다. 분모와 인구 규모 효과를 확인한다. | “연락/방문 업무량이 많다” 또는 “위험도가 낮다” |
| `P1` 낮음 + `P2` 높음 | 주민등록상 절대 수는 작고 혼합-snapshot 비율은 상대적으로 높다. 작은 분모·경계·소수 셀을 먼저 확인한다. | “실제 독거·고립이 집중돼 있다” |
| `P1` 낮음 + `P2` 낮음 | 현재 두 주민등록 수요-context proxy가 상대적으로 낮다. 다른 위험신호나 실제 필요가 없다는 뜻은 아니다. | “돌봄 수요가 없다” |

핵심 지표는 자원을 자동 배정하지 않는다. 담당자가 실제 접촉 기록, 시설 접근성, 운영 용량, 사건 맥락을 확인한 뒤 아웃리치 계획을 승인한다.

## 5. 복지자료의 허용된 사용법

`processed/welfare_basic_livelihood_2024_validation.json`에 따르면 현재 162개 행정동 중 158개만 2024년 원천과 1:1 연결되며 운서1·2동과 아라1·2동은 분할 전 값이라 배분하지 않았다. 다음 규칙을 지킨다.

- 생계·의료·주거·교육 급여를 각각 **기존 지원 맥락/업무 부하**로만 표시한다.
- 네 급여를 합산해 중복 제거된 사람 수처럼 사용하지 않는다.
- 주민등록상 65세 이상 1인세대 수에서 급여 건수를 빼지 않는다.
- 네 분할 행정동 값은 `NULL / unresolved split`로 표시하며 0으로 채우지 않는다.
- 복지자료가 높은 동을 “이미 충분히 지원되는 동”, 낮은 동을 “미수혜 동”으로 단정하지 않는다.

실제 미수혜 규모를 계산하려면 같은 기준기간의 `필요/자격 판정 대상`, `실제 서비스 신청·수급·이용`, `개인 단위 중복제거 키`, `적법한 결합 근거`가 모두 필요하다.

## 6. 정규화·가중치 보정 계획 — 아직 계산하지 않음

### 6.1 무가중 기준선

첫 버전은 `P1`, `P2`, `D1`, `D2`의 원값과 순위를 각각 공개한다. 단순 평균이나 동일 가중치도 임의 선택이므로 종합점수로 만들지 않는다. 운영자가 선택한 동을 기록해 후속 검증의 기준선으로 삼는다.

### 6.2 분포 안정화

충분한 월별 기준선이 쌓이면 다음 순서로 후보 변환을 비교한다.

1. 원천 범위·결측·분모를 점검하고 날짜와 경계를 같은 버전으로 고정한다.
2. 극단값은 오류인지 실제 도서/대규모 동 특성인지 먼저 확인한다. 윈저라이징은 분포를 본 뒤 사전에 고정한 하·상위 분위수에서만 적용하며 임의로 값을 자르지 않는다.
3. 규모와 비율은 별도로 변환한다. `percentile rank`, 평균·표준편차 기반 `z-score`, 중앙값·MAD 기반 `robust z-score`를 안정성·설명가능성으로 비교한다.
4. 작은 분모의 비율은 신뢰구간 또는 empirical-Bayes shrinkage 후보를 검토한다. 보정 전 원값과 분모를 항상 함께 보인다.
5. 강화·옹진 같은 도서/농촌과 고밀도 도시동의 접근성 분포가 구조적으로 다르면, 전체 인천 순위와 사전 정의한 동질 지역군 내 순위를 함께 평가한다. 사후에 유리한 집단만 골라 비교하지 않는다.

### 6.3 가중치 학습과 backtest

가중치는 전문가 감이나 데모 편의를 위해 정하지 않는다. 다음 운영 결과를 같은 기간·같은 지리로 확보한 뒤에만 후보를 학습한다.

- `completed_outreach_within_policy_time / assigned_outreach`
- `confirmed_need / completed_outreach`
- `completed_service_connection / confirmed_need`
- `unhandled_or_expired_cases / assigned_outreach`
- 방문거리, 담당자 시간, 재접촉 수와 같은 자원 소요

평가 절차는 다음과 같다.

1. 과거 시점으로만 다음 기간을 예측하는 walk-forward 검증을 사용한다.
2. 특정 구의 패턴을 외운 모델인지 확인하도록 leave-one-district-out 또는 공간 블록 검증을 병행한다.
3. 무가중 scorecard, 현행 담당자 방식, 제한된 단조 로지스틱/랭킹 모델을 비교한다.
4. 예측 정확도만 보지 않고 상위 검토 구간의 확인률·서비스 연결률, calibration, SLA 충족, 이동시간, 집단별 미처리율을 비교한다.
5. 지표 방향에 정책적·실증적 근거가 확인된 후보에만 단조 제약을 사전 정의한다. 주민등록상 고령·1인세대 proxy만으로 우선도 방향을 확정하지 않는다.
6. 시간대·계절·행정개편에 대한 민감도와 순위 안정성을 확인하고, 현장 담당자가 오류 사례를 검토한다.
7. 지표 버전, 입력 기준일, 변환식, 학습기간, 검증 결과, 수동 override 사유를 감사로그로 남긴다.

최종 가중치는 이 검증에서 실제 확인·연결 결과를 개선하면서 공정성·자원 guardrail을 지킨 경우에만 채택한다. 그 전에는 `MODEL OUTPUT — UNVALIDATED`이다.

## 7. 목표 설정 규칙

`P1/P2`는 인구 구조를 나타내는 상태 지표라서 “낮추기” 목표를 두지 않는다. 정책 성과 목표는 향후 **제때 완료한 아웃리치, 확인된 필요, 실제 서비스 연결, 미처리 감소** 같은 운영 결과에 둔다.

현재 숫자 목표나 SLA 시간을 정하지 않는다. 먼저 평시·폭염/한파 등 수요 급증기를 포함한 실제 기록에서 다음 기준선을 만든다.

- 중앙값, 사분위범위, 상위 꼬리, 결측률
- 구·도서/내륙·서비스유형·수요 단계별 분포
- 담당자 수, 근무시간, 이동시간, 시설 가용량
- 현행 방식의 완료율, 확인률, 연결률, 미처리율

그 뒤 지자체가 정한 법·정책상 응답 기준과 실제 가용 용량을 anchor로 top-down 목표와 bottom-up 가능 범위를 비교한다. 근거 없는 “상위 20%”, “위험점수 70점”, “2시간 SLA”를 이 문서가 임의로 확정하지 않는다.

## 9. 구현 수용 기준

1. 기본 지도는 `P1` 버블과 `P2` 채색을 독립 토글로 제공한다.
2. `P2`가 보이는 모든 지도·툴팁·범례에 2026-07-31 분자와 2026-06-30 분모의 **혼합 snapshot이며 동시점 비율이 아니라는 경고**를 항상 표시한다. 도움말 안에만 숨기지 않는다.
3. 모든 툴팁에 지표명, 분자, 분모, 각 기준일, 경계 기준일, `map_unit_status`를 표시한다.
4. `P1/P2`를 수요-context proxy로 명시하며 실제 독거·고립·동거 여부, 서비스 적격성, 사례·연락/방문 업무량, 미수혜·고위험 인원으로 표현하는 UI 문자열과 API 필드가 없다.
5. 복지 급여 자격을 합산하거나 인구에서 차감하는 코드가 없다.
6. 162행정동 통계와 156지도구역의 합계 보존 및 비율 재계산 검증을 CI에서 재실행한다.
7. 공급·접근 후보는 완결 조건을 통과하기 전 “참고/데이터 미완성”으로 표시하고 종합점수에 들어가지 않는다.
8. 합성 이상징후와 합성 가구는 화면·API·발표자료 모두에서 실데이터와 구분된다.
9. 종합점수와 숫자 목표는 운영 기준선·backtest·공정성 검토 승인 전 배포하지 않는다.
